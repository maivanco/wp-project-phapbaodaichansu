# PhapBaoDaiChanSu Project Guidelines & AI Agent Rules

This document serves as the single source of truth for AI agents (and developers) working on the **PhapBaoDaiChanSu** codebase. Read this file to understand the architecture, project layout, build tools, container setup, and explicit token-efficiency directives.

---

## ⚡ Token-Saving & Efficiency Rules for AI Agents

1. **NEVER scan vendor / third-party plugin directories or `node_modules`**:
   - **EXCLUDE**: `node_modules/`, `src-configs/plugins/woocommerce/`, `src-configs/plugins/wordpress-seo/`, `src-configs/plugins/advanced-custom-fields-pro/`, `src-configs/plugins/akismet/`, `src-configs/plugins/interactive-3d-flipbook-powered-physics-engine/`, `src-configs/plugins/mousewheel-smooth-scroll/`, `src-configs/plugins/webp-uploads/`.
   - **Reason**: These are large vendor packages. Scanning them wastes thousands of tokens and causes timeouts. Only inspect these directories if explicitly instructed to debug or extend a specific vendor plugin.
2. **DO NOT edit files in `dist/`**:
   - `src-configs/themes/default-theme/dist/` contains compiled CSS, JS, and assets generated by Vite.
   - Always edit source code in `src-configs/themes/default-theme/assets/` or theme PHP files.
3. **Scope searches to relevant directories**:
   - Custom Theme Code: `src-configs/themes/default-theme/`
   - Custom WP Configs: `src-configs/configs/`
   - Docker & Infrastructure: root `Dockerfile`, `Caddyfile`, `docker-compose.*.yml`, `start.*`
4. **WP-CLI Execution**:
   - Do NOT attempt to run `wp` directly on host unless WP-CLI is installed. Use the `cli` container:
     `docker compose -f docker-compose.prod.yml -f docker-compose.local.yml exec cli wp <subcommand>`

## 🧰 Tech Stack Summary

| Layer | Technology | Description / Details |
|---|---|---|
| **App Server** | **FrankenPHP** (Caddy embedded) | Modern PHP server replacing Nginx + PHP-FPM (`dunglas/frankenphp` Docker image). |
| **CMS** | **WordPress** | Core application installed in `/app/public/`. Configured in `src-configs/configs/wp-config.php`. |
| **Database** | **MySQL 8.0** | Relational DB running in `db` container with volume `db_data`. |
| **Database UI** | **phpMyAdmin** | Accessible at `http://localhost:8081` in local environment. |
| **Async Cron** | **WP-CLI Cron Container** | `cron` container running `wp cron event run --due-now` every 60s (`DISABLE_WP_CRON` is set to `true`). |
| **Frontend Build** | **Vite + Tailwind CSS v4** | Vite 5/6 with `@tailwindcss/vite` plugin. Output targets `src-configs/themes/default-theme/dist/`. |

## 🔄 Development Workflows & Commands

### 1. Starting Local Environment
```bash
./start.local
```
- Ensures `.env` exists (copies `env.default` if missing).
- Runs `docker compose -f docker-compose.prod.yml -f docker-compose.local.yml up -d`.
- Runs `npm install` if `node_modules` is missing.
- Launches Vite dev server (`npm run dev`) on port `5173`.

### 2. Service URLs
- **WordPress Site**: `http://pbdcs.localhost`
- **phpMyAdmin**: `http://localhost:8081`
- **Vite Dev HMR**: `http://localhost:5173`

### 3. Stopping Services
```bash
docker compose -f docker-compose.prod.yml -f docker-compose.local.yml down
```

### 4. Frontend Asset Compilation
```bash
# Production Build (outputs to src-configs/themes/default-theme/dist)
npm run build

# Start Dev Watch Server
npm run dev
```

### 5. WP-CLI Commands via Docker
```bash
# Example: List active plugins
docker compose -f docker-compose.prod.yml -f docker-compose.local.yml exec cli wp plugin list

# Example: Run due cron tasks manually
docker compose -f docker-compose.prod.yml -f docker-compose.local.yml exec cli wp cron event run --due-now
```

## 🔒 Important Architectural Rules & Security

1. **WordPress File Editing Disabled**:
   - `DISALLOW_FILE_EDIT` and `DISALLOW_FILE_MODS` are set to `true` in `wp-config.php`. Theme/plugin files cannot be installed or edited via the WordPress Admin dashboard.
2. **WP Cron Execution**:
   - `DISABLE_WP_CRON` is set to `true` in `wp-config.php`. Standard visitor-triggered cron is disabled. The dedicated `cron` Docker container runs scheduled tasks automatically every 60 seconds.
3. **Caddy Security Directives**:
   - Requests to `/wp-config.php` and `/.ht*` return `403 Forbidden`.
   - Execution of PHP scripts inside `/wp-content/uploads/` is strictly prohibited by Caddy.
4. **Vite Hot Module Reloading (HMR)**:
   - `vite.config.js` includes a custom plugin (`theme-php-full-reload-and-build`) that listens for changes to `.php` files inside `default-theme`. Editing PHP files automatically triggers asset re-building and live reloads the browser.
